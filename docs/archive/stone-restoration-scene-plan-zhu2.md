# 残缺石像补全 · PC 端 Three.js 实施方案

> 文档状态：历史实施基线。它记录第一版石像单场景的目标，并非当前三个独立场景的完整实现说明，也不是计划中的连续世界方案。当前代码与运行入口以 [项目 README](../../README.md) 和 [多场景交接指南](../multi-scene-handoff-guide.md) 为准；未来滚动游历方案见 [连续世界方案](../continuous-world-plan.md)。本方案中的独立中景小塔已根据视觉反馈从石像场景移除，素材仅留档。

## 1. 项目目标

构建一个仅面向桌面浏览器的沉浸式 2.5D 遗迹场景。画面以 `zhu2` 调整版作为唯一完整远景，主视觉为一尊残缺石像。用户点击石像后，缺损区域逐步恢复为同一尊石像的完整形态。

最终体验必须同时满足：

- 静止画面接近一幅完整的旧纸水彩画。
- 滚动和指针移动时出现克制、自然的空间视差。
- 石像修复表现为缺损区域逐步补全，而不是两张无关图片切换。
- 主石像始终是唯一视觉中心，远景塔群只承担环境叙事。
- 页面只实现 PC 版，不包含移动端素材、布局和交互适配。

## 2. 固定技术路线

- 构建工具：Vite。
- 开发语言：TypeScript。
- 三维渲染：Three.js。
- 动画控制：GSAP。
- 相机：PerspectiveCamera，FOV 固定为 `26°`。
- 远近融合：自定义 ShaderMaterial，不使用 `THREE.Fog`。
- 纸纹：全屏后处理，固定在屏幕空间。
- 图像准备：使用生成式图像编辑直接得到可交付素材，不建立 Python 批处理或自动抠图管线。
- 场景摆放：在 TypeScript 配置中人工调节尺寸、位置、深度和视觉权重，不依赖自动生成的图片元数据 JSON。

## 3. 素材规范

### 3.1 远景背景

输入：`zhu2.png`。

输出：`public/assets/background-zhu2-graded.png`。

处理要求：

- 保留古城、中央塔、河流和远山的整体关系。
- 移除右下角水印以及所有文字、Logo 和印章。
- 背景整体降低约 20% 对比度和约 12% 饱和度。
- 抬灰最深线条并适度降低细节锐度。
- 弱化原始纸纹，避免与屏幕空间纸纹叠加。
- 维持宽幅 PC 构图，中央塔位于画面中心偏左区域。
- 保留充足的浅色天空，不增加新人物或新建筑。

### 3.2 主石像双状态

输出：

```text
public/assets/statue-intact.png
public/assets/statue-broken.png
```

两张图片必须满足：

- 使用同一完整石像母版连续生成。
- 画布、位置、比例、身体轮廓、双手、衣纹、莲座和光线保持一致。
- 均为正立面坐姿，背景真实透明。
- 不含地面、投影、光环、碎片、文字、水印或其他物件。
- 完整态具有清晰但克制的完整面部和冠饰。
- 残缺态只破坏头部、面部和少量冠饰区域。
- 破损必须表现为不规则石材断面、孔洞和裂缝，不得出现马赛克、模糊块或规则遮挡。

### 3.3 中景与前景

以下是第一版素材计划：其中 `midground-pagoda.png` 已不再由当前石像场景加载；`foreground-terrain.png` 仍在使用。

中景和前景输出：

```text
public/assets/midground-pagoda.png
public/assets/foreground-terrain.png
```

- `midground-pagoda.png` 为单体、严格正立面、透明背景的古塔，线条和矿物色与远景统一。
- `foreground-terrain.png` 为一条横向连续的岩石地形带，包含风化石板、浅土脊和稀疏枯草，四周真实透明。
- 两张素材均不得包含人物、文字、水印、地面投影或矩形纸底。

### 3.4 视觉验收

素材进入工程前逐张确认：

1. 单图只有一个可用主体，远景背景除外。
2. 主体为正立面，没有四十五度透视。
3. 旧纸水彩、细铅笔线、骨白石灰色调保持统一。
4. 不存在水印、文字、纸底矩形边缘或不自然投影。
5. 主石像双状态在叠加时，除头部缺损区外不存在明显跳位。

## 5. 场景构成

### 5.1 深度层级

| 层级 | 内容 | 建议 Z 值 | 作用 |
|---|---|---:|---|
| 远景 | `zhu2` 背景板 | `-100` | 建立古城环境与远山天际线 |
| 空气层 | 半透明暖灰水彩层 | `-55` | 拉开背景与主体距离 |
| 中景 | 正立面透明古塔 | `-43` | 建立主体与古城之间的尺度过渡 |
| 主景 | 主石像双状态叠层 | `-20` | 视觉中心和交互主体 |
| 地面 | 水平渐变 Plane | `-18` 至远景 | 承接石像，遮住背景底部空间冲突 |
| 前景 | 横向岩石地形带与稀疏石粉 | `-11` 至 `-14` | 增加近景遮挡和明显视差 |

各层必须使用真实 Z 轴间距。相机移动时，近景位移明显、背景位移轻微。

### 5.2 面片规则

- 图片面片宽高比严格依据原图尺寸计算，不允许拉伸。
- 主石像的两张状态图使用完全相同的 PlaneGeometry、位置和缩放。
- 透明材质启用 `transparent` 和小于 `0.05` 的 `alphaTest`。
- 透明面片使用 `depthWrite: false`，避免前后透明区域互相切边。
- 背景板保持完整画面，不拆分其中的塔、街道、人物和河流。

### 5.3 地面

地面使用水平 PlaneGeometry，顶点远端略低于背景底部。片元颜色从近处浅砂岩灰逐渐过渡到远处背景纸色，并加入低频噪声打散纯色渐变。

地面不得使用写实阴影贴图。主石像脚下只保留低对比、软边接触阴影，避免读取成悬浮贴纸。

## 6. 相机与视差

### 6.1 相机

```ts
new THREE.PerspectiveCamera(26, width / height, 0.1, 300)
```

初始相机位于主石像前方，镜头观察点略高于莲座中心。相机只进行小幅平移和前后推进，不做明显旋转。

### 6.2 滚动推进

- 页面提供约 `220–260vh` 的滚动距离。
- 滚动进度映射到相机 Z 轴的有限推进范围。
- 相机目标值与实际值通过阻尼插值连接。
- 背景保持近似静止，主石像和地面产生可辨识但不过度的视差。

### 6.3 指针视差

- 将指针位置归一化到 `[-1, 1]`。
- 相机 X 偏移不超过约 `±0.9` 个场景单位。
- 相机 Y 偏移不超过约 `±0.35` 个场景单位。
- 每帧向目标值逼近，不直接写入指针坐标。

## 7. 距离溶解 Shader

顶点阶段计算世界坐标到相机的距离，并传递给片元阶段。

片元阶段：

```glsl
float dissolve = smoothstep(uNear, uFar, vDistance);
float weight = dissolve * uMaxDissolve;
vec3 finalColor = mix(texel.rgb, uPaperColor, weight);
```

要求：

- 混合目标是页面背景纸色，不是纯白。
- 背景最大溶解权重约为 `0.58–0.65`。
- 主石像最大溶解权重低于 `0.12`，保持视觉重量。
- 颜色、饱和度和明度同时向背景收敛。
- 不使用灰色雾层覆盖画面。

## 8. 石像补全交互

### 8.1 状态机

```text
broken → restoring → restored → reversing → broken
```

动画进行中禁止重复触发，完成后重新开放点击。

### 8.2 补全方式

- 残缺态始终作为底层。
- 完整态作为同位置叠层，只在头部缺损范围内逐步显示。
- 显示边界由径向距离、低频噪声和时间进度共同决定。
- 边界加入很窄的暖石色亮边，表示修复正在发生。
- 使用 16 块程序化 TetrahedronGeometry 石片，从缺损区四周向头部汇聚；位置由固定种子生成，刷新页面后保持一致。
- 石片运动与补全 Shader 使用同一个修复进度，反向恢复时自动沿原路径退散。
- 石粉粒子从缺损区域附近出现并逐渐收拢、消散。
- 动画结束后完整头部完全覆盖残缺断面。

不得对整尊石像执行普通交叉淡化。

### 8.3 时间建议

| 阶段 | 时间 | 表现 |
|---|---:|---|
| 唤醒 | `0–0.25s` | 交互提示收起，缺损边缘轻微提亮 |
| 聚合 | `0.25–1.15s` | 石粉向缺口汇集，完整纹理开始显现 |
| 成形 | `1.15–2.05s` | 完整面部由内向外稳定扩展 |
| 收束 | `2.05–2.45s` | 亮边和石粉消退，进入完整态 |

反向过程控制在约 `1.2–1.5s`，表现为补全层沿缺损边缘退回。

### 8.4 输入方式

- 点击石像本体。
- 点击页面右侧主操作按钮。
- 主操作按钮支持 `Enter` 和 `Space`。
- 动画期间更新状态文案，但不遮挡石像。
- 主按钮底部显示修复进度条，并同步设置 `aria-busy` 与 `aria-pressed`。
- 修复过程依次显示“边缘苏醒、石片聚合、面容补全、修复收束”四阶段状态。
- 完成态显示克制的“完整 · 修复完成”标记；开始回溯后自动收起。

## 9. 屏幕空间纸纹

使用 EffectComposer 增加全屏后处理：

- 噪声采样基于 `gl_FragCoord`，不使用世界坐标或模型 UV。
- 纸纹不随相机缩放或移动。
- 强度保持在低水平，只打散过于干净的数字渐变。
- 纸纹使用暖灰或中性灰，不增加明显彩色噪点。
- 加入极轻的边缘暗角，使视线回到主石像。

## 10. PC 页面布局

- WebGL 画布固定铺满浏览器窗口。
- 页面左上角放置项目标题和一行引导文字。
- 页面右侧中部放置主操作按钮与状态文案。
- 底部显示克制的滚动提示。
- UI 使用半透明纸色、细描边和大面积留白，不使用高饱和按钮。
- 页面不包含导航栏、卡片列表或与核心体验无关的功能区。
- 不实现手机断点、触摸专用布局和竖屏素材。

## 11. 性能与兼容性

- 目标浏览器：桌面版 Chrome、Edge、Safari 的当前稳定版本。
- 渲染像素比上限为 `2`。
- 图片加载完成前显示纸色加载层，避免白屏闪烁。
- WebGL 不可用时显示静态背景和明确提示。
- 动画循环只更新必要 uniform、相机和粒子状态。
- 页面失去可见性时降低或暂停非必要粒子更新。
- 首屏图片总量控制在合理范围，不加载未使用的原始素材。

## 12. 开发顺序

1. 完成远景背景、完整石像和残缺石像三张最终素材。
2. 建立 Vite + TypeScript + Three.js 项目。
3. 完成背景板、中景古塔、地面、主石像和前景岩带的静态构图。
4. 加入 26° 相机、滚动推进和指针阻尼视差。
5. 加入距离溶解 Shader 与屏幕空间纸纹。
6. 加入石像双状态局部补全 Shader。
7. 加入石粉粒子、状态机和 UI 提示。
8. 执行生产构建、桌面浏览器检查和交互验收。

## 14. 历史方案的不可变更项

以下约束适用于当时的石像单场景。新增古迹主题或连续世界时，应先重新评估，而不是照搬为永久项目约束。

1. 不使用 `zhu1.png`。
2. `zhu2` 是唯一完整背景板，不拆分内部元素。
3. 仅实现 PC 版。
4. 场景使用 Three.js 的真实 Z 轴结构。
5. 相机采用约 `26°` FOV。
6. 不使用 `THREE.Fog`。
7. 纸纹固定在屏幕空间。
8. 残缺态与完整态来自同一石像母版。
9. 修复过程只改变缺损区域。
10. 不引入 Python 图片处理脚本或自动素材元数据管线。
