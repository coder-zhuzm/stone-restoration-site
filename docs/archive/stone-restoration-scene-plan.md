# 残缺石像补全 · 纵深场景实现方案

> 文档状态：最初的 19 张素材探索方案，作为历史参考保留。它包含 `zhu1`、手机陀螺仪、未对齐的石像双状态等后来放弃的设想，不代表当前 PC 项目的实现或待办。当前三个独立场景以 [项目 README](../../README.md) 和 [多场景交接指南](../multi-scene-handoff-guide.md) 为准；计划中的单一滚动世界见 [连续世界方案](../continuous-world-plan.md)。

## 1. 项目目标

用现有 19 张 AI 素材搭建一个带明显空间纵深的东方遗迹场景。

核心体验：

1. 初始状态展示一尊残缺石像。
2. 用户点击石像后，缺损部位逐步复原，最终变为完整石像。
3. 场景随鼠标或手机陀螺仪产生轻微视差，让平面素材看起来像有前、中、后景的立体空间。
4. 第一版先验证场景、纵深和“残缺 → 完整”的交互，不强制先抠图或修复素材。

这不是严格的 3D 建模项目，而是用多层 2.5D 合成、透视、遮挡、光影和视差，低成本获得近似三维的效果。

## 3. 整体画面构图

### 3.1 画面结构

建议采用横屏沉浸式单场景，桌面端比例以 `16:9` 为主，手机端裁切成竖屏而不是整体等比缩小。

```text
后景 Z1：泛黄纸张纹理 + 10/19 寺塔全景 + 雾气
远景 Z2：16 彩塔、05 立像，轻微虚化
中景 Z3：06/09 建筑轮廓 + 13/14 地形
主景 Z4：03/04 主石像 + 11 石台
前景 Z5：12 碎石、局部暗角、尘埃
界面 Z6：极简标题、交互提示、修复进度
```

### 3.2 主体位置

- 主石像位于画面中心略偏下，约占桌面高度的 `48%–58%`。
- 主像底部用 `11` 压住原图底边，使它看起来真正坐在场景里。
- 彩塔 `16` 放在左后方或右后方，尺寸约为主像的 `35%`。
- `10` 或 `19` 作为横向远景铺满，不要同时完整展示两张，避免画面重复。
- 前景碎石只占画面下沿，不能挡住主像手部和头部。

### 3.3 视觉基调

- 主色：骨白、石灰灰、旧纸黄、矿物橙红。
- 背景不要纯白，建议 `#e8dfca` 到 `#b7a681` 的柔和渐变。
- 四周用轻暗角收视线，中心保留暖色微光。
- 不要做霓虹、赛博、玻璃拟态；重点是“古物修复”和“尘封被唤醒”。

## 4. 交互流程

### 4.1 初始状态

- 场景缓慢呼吸：远景几乎不动，中景轻移，前景移动稍明显。
- 残缺石像 `03` 保持清晰。
- 石像周围只有非常弱的尘埃漂浮。
- 鼠标靠近石像时，石像边缘出现低强度暖光，提示可点击。
- 文案只保留一句：`触碰残缺，唤回原貌`。

### 4.2 点击修复

总动画建议 `1.8–2.4 秒`，过程分四段：

1. **聚焦（0–300ms）**：镜头向主像轻推近，背景亮度下降约 8%。
2. **碎片回归（250–1000ms）**：用 `12` 的局部碎片或 CSS 粒子从周围向头部聚拢。
3. **形态补全（600–1700ms）**：`03` 局部淡出，同时通过遮罩逐步显露 `04`。
4. **稳定（1500–2200ms）**：完整石像亮度回落，尘埃散开，显示一句简短结果文案。

完成文案建议：`残缺并未消失，只是等待被看见。`

### 4.3 再次点击

第一版建议支持再次点击恢复残缺态，方便反复观察效果。

- 完整态 → 残缺态控制在 `800–1200ms`。
- 不必反向播放所有碎片动画，只做光线熄灭、遮罩回退和轻微尘落。

## 5. 不修图先实现的 MVP 方法

目标是先验证体验，不在素材处理上阻塞。

### 5.1 最小技术方案

用两个绝对定位、完全重叠的 `<img>`：

```html
<div class="statue" data-restored="false">
  <img class="statue-broken" src="/assets/source/03-578004cac95fe157343cdaaa0ca82f8e.png" alt="残缺石像">
  <img class="statue-restored" src="/assets/source/04-7360231ce0ac2ded88a14f6c033e675f.png" alt="完整石像">
</div>
```

完整态初始隐藏：

```css
.statue {
  position: relative;
  width: min(42vw, 560px);
  aspect-ratio: 1 / 1;
  cursor: pointer;
}

.statue img {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: contain;
  transform-origin: 50% 65%;
  transition: opacity 1.1s ease, filter 1.1s ease, transform 1.1s ease;
}

.statue-restored {
  opacity: 0;
  clip-path: circle(0% at 50% 36%);
  filter: brightness(1.3) saturate(.8);
  transition: clip-path 1.4s cubic-bezier(.2,.8,.2,1), opacity .45s ease, filter 1.4s ease;
}

.statue[data-restored="true"] .statue-broken {
  opacity: 0;
  transform: scale(1.015);
}

.statue[data-restored="true"] .statue-restored {
  opacity: 1;
  clip-path: circle(78% at 50% 36%);
  filter: brightness(1) saturate(1);
}
```

点击切换：

```js
const statue = document.querySelector('.statue');

statue.addEventListener('click', () => {
  const restored = statue.dataset.restored === 'true';
  statue.dataset.restored = String(!restored);
});
```

### 5.2 两张图对不齐的临时处理

不要追求整张图完全重合，先只让以下三处大致一致：

1. 莲座中心；
2. 肩部宽度；
3. 头部中心线。

通过各自独立的 `scale()` 和 `translate()` 校正，例如：

```css
.statue-broken   { transform: translate(0, 1.5%) scale(.96); }
.statue-restored { transform: translate(1%, 0) scale(1.02); }
```

具体数值以浏览器实际画面对齐为准。第一版重点是“看得懂发生了补全”，不是做到电影级变形。

## 6. 纵深与视差实现

### 6.1 图层参数建议

| 图层 | 移动幅度 | 缩放 | 模糊 | 亮度 |
|---|---:|---:|---:|---:|
| 后景 Z1 | 2–4px | 1.03 | 1–2px | 0.82 |
| 远景 Z2 | 5–8px | 1.04 | 0.8px | 0.88 |
| 中景 Z3 | 10–14px | 1.05 | 0–0.5px | 0.94 |
| 主景 Z4 | 14–18px | 1.00 | 0 | 1.00 |
| 前景 Z5 | 22–30px | 1.08 | 0.5–1px | 0.78 |

### 6.2 鼠标视差

把指针位置映射到 `-1 ~ 1`，通过 CSS 变量驱动各层：

```js
window.addEventListener('pointermove', (event) => {
  const x = event.clientX / window.innerWidth * 2 - 1;
  const y = event.clientY / window.innerHeight * 2 - 1;
  document.documentElement.style.setProperty('--look-x', x.toFixed(3));
  document.documentElement.style.setProperty('--look-y', y.toFixed(3));
});
```

```css
.layer[data-depth="3"] {
  transform: translate3d(
    calc(var(--look-x, 0) * -14px),
    calc(var(--look-y, 0) * -9px),
    0
  ) scale(1.05);
}
```

所有移动都要加阻尼或缓动，不能让图层紧跟鼠标抖动。推荐用 `requestAnimationFrame` 插值；如果项目已经使用 GSAP，可用 `quickTo`，不必为这一项单独引入大型依赖。

### 6.3 移动端

- 默认用很慢的自动漂移代替陀螺仪，避免弹权限框。
- 触摸拖动可轻微改变视角。
- 开启 `prefers-reduced-motion` 时关闭视差与粒子，只保留淡入补全。

## 7. 素材预处理的第二阶段

MVP 验证通过后再做，不要放在第一步。

### 7.1 需要处理的素材

优先顺序：

1. `03` 和 `04`：抠出石像与莲座，统一画布、比例和中心点。
2. `11–14`：去掉纸张背景，用作地貌与前景。
3. `16`：抠出塔体。
4. `10/19`：不必完整抠图，做色彩融合和边缘羽化即可。

### 7.2 输出格式

- 独立物件：透明背景 WebP 或 PNG。
- 大背景：WebP，桌面宽度建议 2400px 左右。
- 透明大图优先 WebP，减少体积。
- 同一个交互对的两张图必须使用相同画布尺寸。

建议输出：

```text
public/assets/processed/
├── statue-broken.webp
├── statue-restored.webp
├── pedestal.webp
├── rock-foreground.webp
├── terrain-mid.webp
├── pagoda-mid.webp
├── background-left.webp
└── background-right.webp
```

### 7.3 精修后的补全方式

将石像拆成三层：

```text
底层：完整石像
中层：残缺石像主体
上层：缺口边缘、灰尘、碎片与发光遮罩
```

动画时只替换缺损区域，而不是让整尊石像交叉淡化。这样身体和莲座保持稳定，用户会更相信是“补全”，而不是“换了一张图”。

## 8. 技术实现建议

### 8.1 推荐技术栈

如果是独立网页：

- Vite + React + TypeScript；
- CSS Transform / Clip-path 完成基础视差与遮罩；
- GSAP 仅在需要更顺滑的时间轴、粒子聚拢时加入；
- 不需要 Three.js，当前素材本质上是二维正视/透视图，强上真 3D 成本高且收益低。

如果只是快速验证：单个 `index.html + CSS + JS` 即可完成 MVP。

### 8.2 组件结构

```text
App
└── RestorationScene
    ├── BackgroundLayer
    ├── ArchitectureLayer
    ├── TerrainLayer
    ├── StatueRestoration
    ├── ForegroundLayer
    ├── DustParticles
    └── SceneHud
```

### 8.3 状态模型

```ts
type RestorationState =
  | 'idle'
  | 'focusing'
  | 'restoring'
  | 'restored'
  | 'reverting';
```

动画执行中要锁定重复点击；只有 `idle` 和 `restored` 可以响应点击。

### 8.4 性能要求

- 首屏图片总量尽量控制在 4–6MB 内，最好小于 3MB。
- 远景和前景使用响应式图片；移动端加载较小尺寸。
- 所有动画只改变 `transform`、`opacity`、`filter`、`clip-path`，避免持续改变布局属性。
- 图片必须预加载完成后再允许点击补全，避免完整态临时空白。

## 9. 响应式处理

### 桌面端

- 主像居中略偏下。
- 建筑与山丘向两侧展开。
- 鼠标视差完整启用。

### 手机端

- 主像高度可提升至屏幕的 `58%–66%`。
- 横幅背景使用 `object-fit: cover`，保持主塔或地平线不被完全裁掉。
- 删除一个次要塔和部分侧景，避免拥挤。
- 交互提示放在主像下方，留出安全区。

## 10. 分阶段执行顺序

### 阶段 A：当天可完成的 MVP

1. 创建单屏场景容器。
2. 放入 `10` 远景、`16` 中景塔、`13/14` 地形、`11` 底座。
3. 将 `03` 和 `04` 重叠校准。
4. 实现点击切换、圆形遮罩和轻微发光。
5. 实现 5 层鼠标视差。
6. 完成桌面与手机基本裁切。

输出目标：用户一眼看懂“这是有纵深的遗迹，点击残缺石像后它会复原”。

### 阶段 B：素材精修

1. 抠图并导出透明 WebP。
2. 统一 `03/04` 的尺寸和姿态中心。
3. 只针对缺损部位制作局部遮罩。
4. 清除 AI 水印、重复纹理和明显纸边。
5. 压缩图片并建立移动端版本。

### 阶段 C：完成表现

1. 加碎片回归、尘埃和光照时间轴。
2. 加完成态文案与音效开关。
3. 调整视差阻尼和景深。
4. 做低动态模式和键盘操作。
5. 最终跨设备验收。

## 11. 验收标准

### 场景

- [ ] 第一眼能分辨至少前景、主景、中景、远景四个层次。
- [ ] 主石像是唯一视觉中心，不被塔或碎石抢焦点。
- [ ] 桌面和手机均无横向滚动、明显空边或主体被裁断。

### 交互

- [ ] 点击残缺石像后，明确感知为“缺损被补全”，而不是普通换图。
- [ ] 补全过程无闪白、跳位、图片延迟加载。
- [ ] 动画中重复点击不会导致状态错乱。
- [ ] 完成后可以再次点击恢复，或有明确的重置操作。

### 视觉

- [ ] 素材纸色能够融合，不出现多张白纸生硬叠在一起的感觉。
- [ ] 视差轻微、稳定，不晕、不抖。
- [ ] 光效只服务于补全过程，不长期压过石像细节。

### 性能与可访问性

- [ ] 中等手机网络下首屏不会长时间空白。
- [ ] 支持触摸操作和键盘 Enter/Space 激活主石像。
- [ ] `prefers-reduced-motion` 下仍能正常完成状态切换。
- [ ] 所有装饰图使用空 `alt`，核心石像有准确替代文本。

## 12. 给执行方的关键提醒

1. 第一版不要先花大量时间逐张抠图，先完成场景和交互验证。
2. 不要把所有 19 张图都塞进首屏；素材越多不等于空间越真实。
3. 主线必须围绕 `03 → 04`，其他石像只是环境叙事。
4. 不要使用整页强烈 3D 旋转；纵深来自遮挡、尺度、移动差和景深。
5. 如果 `03/04` 对齐后仍像“换图”，下一步应做局部头部遮罩，而不是继续堆更多粒子。
6. 优先把桌面横屏体验做准，再针对手机重新排布，不能只做等比缩放。

最终判断标准只有一个：用户不用读说明，也能自然地发现并完成“点击残缺石像，让它恢复原貌”这一动作。
