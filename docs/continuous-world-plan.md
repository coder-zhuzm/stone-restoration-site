# 连续遗迹世界 · 滚动游历与多古迹修复方案

> 状态：下一阶段设计方案，尚未实施。当前可运行版本仍是三个由 URL 切换的独立 PC 场景。本文不把设计目标写成已经完成的功能。

## 1. 目标与边界

目标是让用户在**同一个 Three.js 世界**里滚动前行，沿一条连续的遗迹路线依次抵达多个可修复古迹。前后站点之间保持地貌、光线、纸色和空间方向连贯；相机不会通过页面跳转或整屏换背景完成“旅行”。到达站点时，用户可以点击古迹，观看局部补全，再继续向前或回看。

首个原型可沿用现有石像、五层佛塔和密檐砖塔作为三个“修复站点”，但这只是技术验证顺序，不是最终地理叙事。仍只做 PC 版。新主题可以替换古迹与世界设定，不必绑定佛教塔或旧纸水彩风格。

不把“三张 16:9 背景图横向拼接”当成连续世界；也不把三个现有页面包在一张长网页里。目标是在同一个 WebGL 场景坐标系中组织共享环境、站点、遮挡物、相机路线和多个独立修复状态。

## 2. 当前资产与代码的复用判断

| 项目 | 可复用 | 需要改变 |
|---|---|---|
| 26° 透视相机、距离溶解、屏幕纸纹 | 原理和 Shader 可沿用 | 相机从单段 Z 推进改为沿路线关键帧行进；每段的距离融合需重新校准 |
| 主物件透明面片、Alpha 命中、局部修复 Shader | 可作为单个站点的修复单元 | 由一套全局变量改为每个站点各自的材质、状态、碎片和点击范围 |
| 石像、两座塔的完整／残缺双状态 | 可用于第一版原型，需重新检查构图和边缘 | 新主题必须重新制作自己的双状态；现有古迹不能直接代表其他文化的建筑 |
| 三套远景、中景、前景 | 可作氛围和局部素材参考 | 不能直接无缝相接；需统一地理路线、地平线、光照、比例和过渡素材 |
| URL 场景注册表与三个导航链接 | 可保留旧版作为对照 | 连续世界改为世界／站点数据，不再靠 `?scene=` 切换页面 |

尤其要注意：石像场景的 `zhu2` 远景已画入一座大型塔。它只是背景图中的像素，不能成为可走近修复的独立古迹；若新世界的路线经过该位置，应重新编辑该段远景或调整路线，避免背景塔与透明主塔重复。

现有 `src/main.ts` 只创建一个 `THREE.Scene`、一个主物件、一套修复材质与状态，并依据当前 URL 载入一份 `SCENE_CONFIG`。这套结构可做单站点原型，不能靠增加配置项直接变成多个同时存在的站点。

## 3. 世界构图与路线

### 3.1 先画路线图，再生成图

先以低精度草图标出：起点、每个古迹站点、站点间的地貌过渡、远山／道路／河流等贯穿线索、可遮挡接缝的地形与建筑，以及相机在每站的正面观察位置。原型可尝试“古城边缘 → 河谷寺院 → 黄土石窟”的顺序，但这只是叙事提案；在素材开工前必须验证它能形成可信的一条路。

每站都有三个范围：抵达前的预告、可交互的正面视区、离开后的余韵。站点之间应有可见的行进过程，而不是远景交叉淡化后瞬间出现另一处遗迹。

### 3.2 空间规则

- 世界在 X/Z 方向延展，地面与环境连续；每个站点的主物件仍可使用竖直面片，但相机抵达时须接近正面，不让侧移暴露纸片厚度。
- 远景可使用相互衔接的宽幅段或统一长幅背景；中景、前景和道路／河岸承担遮挡、接地和景深。每段都有明确的世界坐标与覆盖范围。
- 不为每站叠加一张“完整的独立天空＋地面”背景板。接缝处要靠连续地形、重叠画幅和真实遮挡解决，而非只靠不透明淡入淡出。
- 纸纹仍是唯一的屏幕空间承载层；各站素材不重复烘焙强纸纹。
- 26° FOV 是现有画风的基线而非万能数值。若相机路径导致主物件拥挤或长途压缩过强，先调路径与站点间距，再审视 FOV；不为了容纳世界改成广角纸片走廊。

## 4. 交互与相机

滚动进度映射到相机路线的多个关键帧，不再是当前 `camera.z = 起点 - progress × 单一行程`。关键帧至少包含位置、观察点、站点归属、速度区间和画面安全区。经过渡区时可以略微横移或转向，接近古迹时回到正面、减速并让古迹成为唯一视觉中心；所有运动继续使用阻尼。

一个站点对应一个独立修复控制器：`broken → restoring → restored → reversing → broken`。已修复站点在离开、回看时保持状态，不因为新的古迹激活而重置。只有进入当前站点的可交互视区，才显示其修复按钮、悬停轮廓和点击命中；远处站点不能误触。

原型建议在修复动画期间短暂保持当前观察位，结束后恢复滚动推进；此交互规则需要用实际体验确认，不能与滚动目标直接相互争夺相机。低动态模式必须允许快速完成修复和继续前行。

UI 从“石像／佛塔／密檐塔”页面切换导航，改为当前站点名称、修复进度和旅程位置。允许用户向后滚动回看，不以修复完成强制锁定下一个站点。

## 5. 数据与代码改造边界

建议增加世界级数据，而不是继续扩张单个 `RestorationSceneConfig`：

```ts
type WorldDefinition = {
  style: { paperColor: string; fov: number };
  route: CameraKeyframe[];
  environmentSegments: EnvironmentSegment[];
  sites: RestorationSiteDefinition[];
};

type RestorationSiteDefinition = {
  id: string;
  position: readonly [number, number, number];
  interactionRange: { enter: number; leave: number };
  subject: { broken: string; intact: string; size: readonly [number, number] };
  damage: { center: readonly [number, number]; radius: readonly [number, number] };
  copy: { title: string; status: string; completed: string };
};
```

以上只是关系示意，不是可直接复制编译的最终 TypeScript 接口。实现时至少拆出：世界场景装配、相机路线、每站修复控制器、站点交互选择、素材加载管理和 UI 状态投影。`createDistanceMaterial`、`createRepairMaterial`、纸纹后处理及现有碎片算法可以迁移，不复制三份渲染器或动画循环。

纹理应按区域预加载下一站，并为离得很远的区域控制可见性和资源占用；不能无限增加全尺寸背景后首屏一次性加载。所有站点在世界中有稳定 ID 与修复状态。加载失败时应说明具体站点和素材路径，不静默跳过。

## 6. 连续世界所需素材包

### 6.1 世界级素材

1. 世界构图草图：站点顺序、地理线索、相机方向与远景关系。
2. 共用风格卡：纸色、画法、线条、材料、日照与饱和度，跨主题时重新制定。
3. 连续远景母版或互有重叠的背景段：同一地平线、远山形态和光照，边界可比对。
4. 中／前景过渡带：道路、河岸、山脊、残墙、植被等；真实透明、可遮挡背景边界。
5. 地面与接触区域：保证每座古迹有立足处，站点间没有突然断开的地板。

### 6.2 每个修复站点

- 同画布、同尺度、同位置的完整态与残缺态透明主物件。
- 缺损位置、范围、材料与补全方向说明。
- 需要贴图碎片时的透明碎片资产；否则采用程序化碎片。
- 站点文案、接地点、世界坐标、正面观察位和交互范围。

生产顺序和通用改图提示词见 [素材生产指南](asset-production-guide.md)；当前素材的逐张实际提示词见 [素材台账](asset-generation-log.md)。现有三张远景可以当风格参考，不能直接充当无缝世界的三段成品。

## 7. 连续素材的提示词约束

给图像模型的输入至少包含：世界构图草图、共用风格卡、相邻环境段的边缘参考、当前站点主体、这张图的独立用途和画布规格。环境提示词必须写“延续相邻段的地平线、地貌线、光线与纸色，保留主物件位置”，而不是泛泛地说“生成同风格的另一张古迹背景”。

主物件继续遵循“完整母版 → 以母版局部编辑残缺态”，并明确禁止背景、地面、投影和漂浮碎片。过渡带则必须说明它是**一条连续的透明遮挡元件**，不在同图中画多个互不相关的小物件。可直接改写的提示词骨架见素材生产指南第 3–4 节。

## 8. 分阶段实现与验收

1. **构图阶段**：先确认路线草图和风格卡。验收：三个站点在同一地理与视觉叙事里有合理顺序，修复主物件不被画死在背景。
2. **两站原型**：只接入前两个站点及一处过渡，不急于搬完第三站。验收：滚动往返无明显整屏换景、地貌断裂、地平线跳动和纸片侧视；两站可独立修复，状态互不影响。
3. **全路线**：增加第三站和其过渡段，完成站点 UI、资源预加载和降级提示。验收：首屏不过度加载；返回旧站点时保持已修复状态；透明边缘和遮挡顺序正常。
4. **收束**：执行生产构建、检查三个桌面视口与低动态模式，由用户在浏览器里做最终视觉验收。记录实际取舍、素材失败样例与最后采用提示词。

未通过“两站原型”的连续性验收前，不应批量生成整条世界的全部最终图，也不应宣称连续世界已经实现。当前项目的三个独立场景保持可运行，作为对照和回退基线。

## 9. 待拍板事项

- 最终古迹主题与地理路线；是否沿用现有三个主物件。
- 是否始终维持旧纸水彩画法，或为新主题设定另一种统一媒介。
- 修复动画期间是否短暂锁定相机，以及站点可交互的滚动范围。
- 连续远景采用一张长幅母版还是多个有重叠的分段；由构图草图和模型样张决定。

这些选择会改变素材包与代码规模，实施前应以草图和两站样张确认。
